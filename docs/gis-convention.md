# GIS Convention

## 현재 기준

| 항목 | 값 | 상태 |
|---|---|---|
| 원천 데이터 | 원본 데이터에서 확인 | 종류별 확인 필요 |
| DB 저장·거리 연산 | EPSG:5179 | 초기 Migration Geometry 컬럼에 확정 반영 |
| API 입출력 | GeoJSON, EPSG:4326, 경도·위도 순서 | 현재 기준 |
| 거리·고도 단위 | m | 현재 기준 |
| 경사 단위 | % (상승 높이 ÷ 수평 거리 × 100) | 현재 기준 |

미확정 값은 임의로 정하지 않는다. 확정되면 이 표를 갱신한다.

## 좌표와 Geometry

- 모든 Geometry는 SRID, 축 순서, 단위, Geometry 유형을 함께 관리한다.
- 서로 다른 SRID의 Geometry를 암묵적으로 연산하지 않는다.
- 저장 좌표계와 API 좌표계가 다르면 `ST_Transform` 적용 위치와 이유를 SQL에서 분명히 한다. 변환은 API 경계에서 한 번만 한다.
- 거리와 면적은 미터 단위를 올바르게 산출하는 투영 좌표계 또는 `geography`로 계산한다. EPSG:4326 좌표로 직접 거리를 계산하지 않는다.
- 외부 좌표 입력은 유효 범위, SRID, Geometry 유형을 검증한다.

## 공간 질의

- 공간 검색은 먼저 범위(bbox)를 줄여 공간 인덱스를 활용할 수 있게 구성한다.
- 함수로 인덱스 대상 컬럼을 불필요하게 감싸 인덱스 사용을 막지 않는다.
- 경계 포함 여부, 허용 거리, 단위와 정밀도를 요구사항에 맞게 명시한다.
- Geometry 유효성 문제를 조용히 무시하거나 결과를 임의 보정하지 않는다.
- 성능 민감 쿼리는 실제 데이터 규모에서 실행 계획을 확인한다.

## pgRouting

- 경로 탐색은 실제 스키마와 승인된 네트워크 모델을 확인한 뒤 구현한다. Node/Edge 및 비용 컬럼이 있다고 가정하지 않는다.
- 승인된 모델이 `cost`와 `reverse_cost`를 사용한다면 각 방향 의미와 통행 불가 표현을 스키마·pgRouting 버전과 함께 확인한다.
- 출발·도착 좌표를 네트워크에 연결하는 스냅 기준과 허용 거리를 일관되게 적용한다. 허용 거리 값은 미확정이다.
- 경로 후보 생성 방식(`pgr_KSP`, 조건별 `pgr_dijkstra`)과 비용 가중치 기본값은 미확정이다.
- 사용자 코스 계산을 위해 공용 네트워크 원본을 직접 변경하지 않는다.
- 네트워크 버전 저장은 모델과 관리 규칙이 합의된 뒤 적용한다.
- 경로 없음, 단절, 스냅 실패를 서로 구분하고 임의 경로를 생성하지 않는다.

## 분석 결과

- 거리, 예상 시간, 고도, 누적 상승량, 경사도 등은 계산식과 단위를 API 계약과 일치시킨다.
- 경사는 실제 DEM 해상도와 계산 구간 길이에 따라 달라진다. 확인되지 않은 DEM 출처·해상도를 문서만 보고 확정하지 않는다.
- DEM 또는 원천 데이터가 없으면 값을 만들어 내지 않고 결측 또는 분석 불가 상태로 처리한다.

공간 SQL 관리 위치는 [database-convention.md](database-convention.md), REST 표현은 [api-convention.md](api-convention.md), 경계값 검증은 [testing-convention.md](testing-convention.md)를 따른다.
