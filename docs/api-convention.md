# API Convention

## 범위

이 문서는 Backend가 제공하는 REST 계약의 설계 원칙을 정의한다. 실제 endpoint와 필드는 승인된 API 명세와 구현을 기준으로 한다. API 명세 문서 위치는 미확정이다.

## 리소스와 HTTP

- 경로는 `/api`로 시작하고 명사 중심으로 일관되게 구성한다.
- `GET`은 조회, `POST`는 생성 또는 명령, `PUT`은 전체 교체, `PATCH`는 부분 수정, `DELETE`는 삭제에 사용한다.
- 조회는 안전해야 하며, 멱등성이 필요한 동작은 HTTP 의미에 맞게 설계한다.
- 성공한 생성은 `201`, 일반 성공은 `200` 또는 본문이 없을 때 `204`를 사용한다.
- 잘못된 입력은 `400`, 인증 필요는 `401`, 권한 부족은 `403`, 미존재는 `404`, 상태 충돌은 `409`, 예기치 못한 서버 오류는 `500` 계열로 구분한다.

## 데이터 계약

- Controller의 요청·응답은 DTO로 표현하고 DB 내부 구조(VO, 행)를 그대로 노출하지 않는다.
- Bean Validation은 형식 검증에 사용하고 도메인 규칙은 Service에서 검증한다.
- 날짜·시간은 ISO 8601로 직렬화하며 시간대 의미를 보존한다.
- 페이지 방식, 정렬 허용값, 필터 문법, 선택 필드와 `null`의 의미를 endpoint 계약에 명시한다.
- 공간 데이터는 GeoJSON(EPSG:4326, 경도·위도 순서)으로 주고받는다. 세부 기준은 [gis-convention.md](gis-convention.md)를 따른다.
- 대량 공간 조회는 `limit` 또는 bbox로 범위를 제한한다.

## 오류 계약

현재 공통 오류 응답 구조:

```json
{ "status": 400, "code": "INVALID_REQUEST", "message": "요청 형식이나 입력값을 확인해주세요.", "details": [], "traceId": "서버 생성 UUID" }
```

- `status`는 HTTP 응답 상태 코드와 항상 같은 숫자다. Controller가 임의로 채우지 않고 공통 오류 처리에서 설정한다.
- `code`는 대문자 스네이크 케이스의 안정적인 값이다. 현재 공통 코드는 `ErrorCode`에 정의되어 있으며 도메인별 코드는 승인된 API 계약에 추가한다.
- 입력 오류의 필드별 상세는 `details` 배열로 제공하며, 항목은 `field`와 안전한 안내 `message`를 가진다. 추적 식별자는 본문 `traceId`와 `X-Trace-Id` 응답 헤더에 제공한다.
- 스택 트레이스, SQL, 내부 클래스명, 비밀정보는 노출하지 않는다.
- 예상 가능한 비즈니스 오류와 시스템 오류는 공통 예외 처리에서 구분한다.
- 실제로 구현되지 않은 경로 오류 코드를 문서에서 확정하지 않는다. 경로 없음, 스냅 실패, 네트워크 단절은 기능 계약 합의 시 서로 구분한다.

## 변경 관리

기존 소비자를 깨는 경로·필드·타입·의미 변경은 FE와 함께 검토한다. 한쪽 Repository의 추측으로 계약을 변경하지 않으며 협업 절차는 [git-convention.md](git-convention.md)를 따른다.
